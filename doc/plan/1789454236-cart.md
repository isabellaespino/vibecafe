# Plan: Cart

Derived from `doc/study/1789454197-cart.md`.

## Outcome

- A logged-in user can, from a product's detail page, submit a quantity and
  add that product to their cart.
- `/cart/` lists the logged-in user's cart: each product, its quantity, a
  per-line subtotal, and a cart-wide total, all in peso formatting.
- Anyone not logged in who hits `/cart/` or submits the add-to-cart form is
  redirected to a login page at `/accounts/login/`.

**Deferred**: removing/editing cart items, checkout, `Order`/`OrderItem`,
order history, logout, self-registration, password reset — unchanged from
the study.

## Decisions (from the study)

1. New `cart` app: `CartItem` model, add-to-cart view, cart page view, own
   `urls.py`.
2. `CartItem(user FK, product FK, quantity)`, `UniqueConstraint(user,
   product)`, `on_delete=CASCADE` on both FKs, no timestamp field. Cart
   page orders by `product__name`.
3. Add-to-cart is get-or-create-then-`F()`-increment, not a plain
   read-modify-write, to close the double-submit race.
4. Cart total computed via `aggregate(Sum(F("quantity") *
   F("product__price")))`; per-item subtotal via a `CartItem.subtotal`
   property. Both rendered with the existing `₱{{ value|intcomma }}`
   pattern.
5. Login page: project-level `templates/registration/login.html` (new
   `templates/` dir, added to `TEMPLATES[0]["DIRS"]`), `LOGIN_URL =
   "login"`, `LoginView` wired directly in `vibecafe/urls.py` — not the
   full `django.contrib.auth.urls` bundle (avoids half-wired
   password-reset/change surface).
6. No logout view this pass (not requested; `/admin/logout/` covers manual
   testing). No cart-item removal/edit this pass (not requested).
7. Known, accepted caveat: an anonymous POST to `/cart/add/<id>/` redirects
   to login; after logging in, the browser GETs the `next` URL and gets a
   clean `405` (add-to-cart is POST-only) rather than the action replaying.
   Verify this is a 405, not a 500, during manual testing — don't build
   around it.

## Steps

### 1. Auth plumbing (no app yet, just settings + urls)
- [ ] Create `templates/registration/login.html` at the repo root (plain
      HTML form, username/password fields, CSRF token, same no-JS style as
      existing templates).
- [ ] Add `BASE_DIR / "templates"` to `TEMPLATES[0]["DIRS"]` in
      `vibecafe/settings.py`.
- [ ] Add `LOGIN_URL = "login"` to `vibecafe/settings.py`.
- [ ] In `vibecafe/urls.py`, add:
      `path("accounts/login/", auth_views.LoginView.as_view(template_name="registration/login.html"), name="login")`.

### 2. `cart` app
- [ ] `python manage.py startapp cart`; add `"cart"` to `INSTALLED_APPS`.
- [ ] Define `CartItem` in `cart/models.py` per study §4 (`user`,
      `product`, `quantity`, `UniqueConstraint`).
- [ ] `makemigrations cart && migrate`.
- [ ] Add a `subtotal` property to `CartItem`
      (`self.quantity * self.product.price`).

### 3. Add-to-cart
- [ ] `AddToCartForm(forms.Form)` with `quantity =
      forms.IntegerField(min_value=1)` in `cart/forms.py`.
- [ ] `add_to_cart` view in `cart/views.py`: `@login_required`,
      `@require_POST`; validate form; get-or-create + `F()`-increment on
      success (study §5.2); `messages.error(...)` + redirect back to the
      product detail page on invalid input; redirect to `/cart/` on
      success.
- [ ] `path("cart/add/<int:product_id>/", add_to_cart,
      name="add_to_cart")` in `cart/urls.py`; include `cart.urls` from
      `vibecafe/urls.py`.

### 4. Product detail page: add-to-cart form
- [ ] In `products/templates/products/product_detail.html`, add a POST
      form to `{% url 'add_to_cart' product.pk %}`: CSRF token, a
      `quantity` number input (`min="1"`, `value="1"`), submit button.
- [ ] Add a `{% if messages %}` block to the same template to surface
      validation errors from step 3.

### 5. Cart page
- [ ] `CartView` (or function view) in `cart/views.py`: `@login_required`
      (or `LoginRequiredMixin`); query per study §6; pass items + total to
      the template.
- [ ] `cart/templates/cart/cart.html`: table/list of product name,
      quantity, `₱{{ item.subtotal|intcomma }}` per row, and
      `₱{{ total|intcomma }}` at the bottom. Empty-state message when the
      cart has no items (mirrors the homepage's "No products yet.").
- [ ] `path("cart/", CartView.as_view(), name="cart")` in `cart/urls.py`.

### 6. Manual verification
- [ ] `manage.py check`.
- [ ] Anonymous: visit `/cart/` → redirected to `/accounts/login/?next=/cart/`.
- [ ] Anonymous: POST to a product's add-to-cart form → redirected to
      login; confirm this, don't chase further (§7 caveat is expected).
- [ ] Log in (via `/accounts/login/`, using the existing admin superuser
      or a second test account) → confirm login succeeds and redirects
      correctly.
- [ ] Add the same product twice with different quantities → confirm one
      `CartItem` row, `quantity` summed, not two rows.
- [ ] Add a second, different product → cart page shows both, correct
      per-item subtotal and correct grand total, all in `₱` with
      `intcomma` formatting.
- [ ] Submit quantity `0` → confirm a clean validation error message, not
      a 500, and no `CartItem` created/changed.
- [ ] After logging in via the `next=` redirect from an anonymous
      `/cart/add/<id>/` POST attempt, confirm the resulting GET to that
      same URL returns `405`, not `500` (study §5.3 caveat — confirm it's
      clean, don't fix).
- [ ] `manage.py test` exits clean.
- [ ] Per CLAUDE.md: verification uses `manage.py test` and/or a throwaway
      seed in the working `db.sqlite3` that's explicitly cleaned up by
      deleting only the rows this session adds — never `rm db.sqlite3`,
      never bulk `.all().delete()`.

### 7. Commit
- [ ] One commit on a branch off `main` (e.g. `feat/cart`):
      `feat: add cart with login-gated add and cart page`. Rendezvous and
      doc sync are separate subsequent steps.

## Explicitly not doing here

- No remove/edit of cart items.
- No checkout, no `Order`/`OrderItem`.
- No logout view, no password reset/change, no self-registration.
- No resume-intended-action-after-login handling for the POST-only
  add-to-cart caveat (study §5.3).
